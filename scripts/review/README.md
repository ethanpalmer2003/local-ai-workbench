# Repository review

Run the complete review from `C:/AI`:

```powershell
python -m scripts.review
C:/AI/scripts/review/check_repo.bat
```

The default run is scoped to what changed since upstream. `--all` checks every section in a minute, so it never asks; runs expected to pass five minutes ask, through [consent](../shared/consent.py). `--summary` prints one line per section.

The runner executes:

- `checks/layout.py`: component/config ownership, install roots, folder naming, high-level file placement, batch references, and the committed index: every `scripts.*` import resolves in it and no indexed file matches an ignore rule.
- `checks/owned_tokens.py`: a literal one module owns may not be spelled in another, so a copy fails instead of drifting.
- `checks/duplicates.py`: pylint duplicate blocks against a reviewed baseline; opt-in, a minute.
- `checks/annotations.py`: annotation complexity by atoms, nesting and unions, aliases included; above the cap it asks for a record.
- `checks/line_length.py`: no line over 120 except template or token content.
- `checks/bare_any.py`: no parameter or return may be exactly `Any` outside tests; `dict[str, Any]` stays allowed.
- `checks/docs.py`: Markdown placement, roles, budgets, basename casing, links, running-list structure and model-name policy.
- `ruff check` and `ruff format`: the configured lint set, including the [McCabe limit](../../.agents/CODE.md), and the formatting every commit applies.
- `checks/model_references.py`: catalog IDs, workflow defaults, AudioCpp runtime paths.
- `checks/frontend_wiring.py`: HTML/JS asset paths, DOM element ids and injected settings keys.
- `basedpyright`: Python type errors.
- `checks/inventory_code.py`: folder counts, the 20-file and 600/800-line caps, sparse folders.
- `checks/typography.py`: ASCII punctuation only; dashes, curly quotes, the ellipsis and no-break spaces are rejected in tracked text, quoted corpus references excepted.
- `checks/comments.py`: markers, banner rules and commented-out code are rejected; comments that explain why stay.
- `checks/spellings.py` plus codespell: British spellings report the American form and the dictionary catches typos.
- `checks/dead_code.py`: an unused function or class, or unreachable code, through vulture, with overrides and catalog constants exempt ([libraries](LIBRARIES.md)).
- `checks/walrus.py`, `checks/expression.py`, `checks/dynamic_imports.py`: an assignment hidden in a
  comprehension, a condition nesting three operator levels, and a module loaded by a name the source hides.
- `audit/package_audit.py` with deptry: the lock against `pyproject.toml`, installed-package advisories, and
  every import declared while every declaration is imported.
- `checks/network_timeouts.py`: every HTTP call passes `timeout=`; the ASR upload wrapper owns its own.
- `checks/overlay_access.py`: only `config/local_overlay.py` resolves overlay paths; a direct read elsewhere fails.
- `audit/public_audit.py`: overlay vocabulary and input names in tracked text, on every change, so a personal
  name fails at commit instead of waiting for the publish scan that owns the other categories.

Reports go to `runs/state/generated/shared/code_review/<run>/`. The inventory lists the largest functions and excludes generated output, caches, model data, installs and trash. Suppressed McCabe debt stays listed in [complexity debt](GENERATED-COMPLEXITY-DEBT.md), regenerated by the inventory. Which checks run through a tool and which are this repository's own policy: [libraries](LIBRARIES.md). One mistake per check, the line it prints and the fix: [examples](EXAMPLES.md).

## Fixing and finding

Two kinds of section, and the difference decides who acts. `ruff check --fix` and `ruff format` rewrite the
file, and pre-commit applies them on every commit: what can be applied is applied. Every other
section only reports, and the fix belongs to the reader.

A false alarm costs less than a missed defect. A repeated one is a rule change: narrow it by kind, or exclude a
folder rather than list names.

## Duplicate check

The optional embedding check and its code mode: [similarity](SIMILARITY.md). Front-end wiring: [frontend
wiring](FRONTEND-WIRING.md). Both are in the gate.

Each check runs alone, for example `python -m scripts.review.checks.layout`. `checks/docs.py --words` prints every
document by word count with its budget, `--roles` counts documents per role, and `--links` reports pointers,
repeats and unlinked documents; a link fails when it is absolute, uses a backslash, points into an untracked
path, or misses its target. Add `--tests` to run the model-free suite afterwards. Document organization:
[NOTES-CONVENTIONS](../../.agents/NOTES-CONVENTIONS.md).

## Framework validation

This gate is repo-wide and never loads a model. A check that belongs to one framework stays beside that
component:

| Check | Location | Runs at |
| --- | --- | --- |
| Startup contract | `config/<component>/verify*.py`, e.g. [verify_node.py](../config/comfyui/verify_node.py) | launcher |
| Offline contract | `tests/cases/<component>/` | model-free suite |
| Update check | [framework updates](../download/frameworks/UPDATES.md), driven by `update_shared.py` | update run |
| Live preflight | [benchmarks/shared/preflight.py](../benchmarks/shared/preflight.py) | benchmark run |

A framework without a startup validator makes its launcher fail on missing paths instead.

Format what changed with `scripts/review/format_py.bat`; `--all` formats the whole repository. Lint and format share one scope: repository root, Python files only, with `.venv`, `frameworks`, `data`, `trash`, `state`, run outputs and generated `ids.py` excluded. The gate compares formatting too and follows the same scoping; `--no-format-check` skips it. Tool inventory: [TOOLS.md](TOOLS.md).
