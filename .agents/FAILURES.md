# Failure modes

- Two kinds of blocker. A content failure (written code, a document, a generated file) is caught by the suite and the gate, so it blocks a commit or a push. A process failure (how a step is run, read or moved around the repo with) has no natural check, so it is recorded here with the symptom and its replacement.
- When a step fails, name its root cause before continuing, and add a deterministic guard when one exists. A rule alone is the fallback, never the first answer.

| Symptom | Root cause | Replacement |
| --- | --- | --- |
| A commit carries app-written state (logs, run scripts, connection configs) | `git add -A` stages whatever the tree contains | Stage explicit paths; the layout section's committed-index rule refuses an indexed file that matches an ignore rule |
| A committed file imports a module the repository does not have | `git add -u` stages modified paths only, so a new file stayed untracked while the edit that names it was staged | The layout section's committed-index rule refuses an import the index does not carry; still add the new path explicitly |
| A push is rejected for a file past the host limit | An exported bundle or patch was committed unchecked | The gate's `large files` section refuses a tracked file over [the limit](../scripts/review/checks/layout.py) before the push |
| A list keeps an entry that was meant to be removed | A line filter that silently matches nothing | Grep the text after the removal, and make the filter assert the count it expects before it writes; the gate cannot know the intent |
| A validation stage is stale the moment its run ends | The recorded fingerprint was captured before a stage updated what a later stage reads | `stage_runner.run(fingerprint_after=...)` re-reads each stage's inputs after it runs |
| A search walks `frameworks/` or `data/` for minutes, or is refused outright | A recursive scan named an ignored tree | Name one folder, `git grep` inside a checkout, or `python -m scripts.tools.locate_files SUFFIX` for a bounded depth under the model and framework roots |
| A `glob` pattern or a `-Recurse` listing inside `frameworks/`, `data/` or `state/` times out or is refused | The pattern matches at any depth, so naming an ignored tree is already the unbounded walk | Scope it to a tracked folder or use `git ls-files`; the refusal and [code search](CODE-SEARCH.md) name the bounded tool, and [the rules index](README.md) names every agent guide |
| A commit that a hook refused still reads as a success, and the new commit is missing | `git commit ...; git log` reports the exit code of the last command in the chain | Run the commit alone, or chain with `&&`, then confirm `git log --oneline -1` names the new commit |
| A commit aborts with "files were modified by this hook" | `ruff format` rewrote the staged file, so what pre-commit recorded no longer matched the tree | Stage the rewritten file and commit again; nothing needs debugging, and the hook passes on the rerun |
| Every `pwsh` call costs 20-40 s | An unbounded glob or listing over the whole tree | `Select-Object -First N`, `-Name`, or scope the path to one folder |
| The same command re-run three times with the same failure | No root cause was named before the retry | Stop, read the message once, name the cause, then change the command |
| Ran the full gate and suite by hand before committing | The hooks were going to run them anyway: pre-commit runs the scoped gate and suite, pre-push the full set | Commit and let the hooks validate; the entry points now refuse a manual full run without `--manual`, single files and sections need no flag, and `manual_gates.report()` lists every live use |
| Re-ran an 80 s suite to read a number that scrolled past | stdout treated as the record instead of the artifact | Read `artifacts/summary.json` and the closing `[SUITE]`/`[OUTPUT]` lines; the runner writes both, so no result needs a rerun |
| Answered from a whole-tree walk instead of the indexes | Reached for `Get-ChildItem -Recurse` before `cbm_search` or `query_graph` | Structural questions go to the indexes first per [code search](CODE-SEARCH.md), `git grep` for text; the scan refusal names the bounded tool |
| A new test fails on first run against the author's own helper | Asserted an imagined outcome instead of tracing the logic | Hand-trace the kept and removed sets, then assert the exact list; the suite catches the slip in seconds |
| A temp-dir test fails on files the test just wrote | Assertions sit outside the `with TemporaryDirectory` block, after cleanup removed them | Keep assertions inside the block |
| Iterated on a doc budget through full gate runs | Edited blind, one word at a time, paying a gate per attempt | Count first with the docs word counter directly, then run the gate once |
| Non-ASCII punctuation in a doc edit | Typed an en-dash where the repo requires ASCII | Write `-`; the typography section refuses the rest |
| Scratch scripts pile up in `runs/state/temp` | One-off probes written into the tree and left there | Scratch goes to `$env:TEMP` or is deleted the same session; the 7-day scratch prune and the gate prune report are the backstop, not the plan |
| Implemented a placement, then reverted it on stated preference | Guessed at a judgment call (junction vs real dir) instead of asking | When two placements both work, ask with the question tool before implementing |
| Polled a launcher job for minutes after the stack was already serving | A supervising launcher blocks until shutdown, so its job running is the healthy state, not a pending one | Read readiness from ports, health and `/v1/models`, and start it in the background. Rule: [proxies and launchers](../scripts/launchers/PROXIES.md) |
| Wrote a throwaway relaunch script for a service that already has a launcher | Reached for `launch_module` in a scratch file instead of the stack's own entry point, which bypasses its port policy and ownership | Start the stack with `python -m scripts.launchers.<stack>` and stop it with `python -m scripts.launchers.kill_all_services`; the launcher clears or refuses ports, supervises children and tears them down together, so an ad-hoc start leaves duplicates nobody owns |
| A rewrite replaced nothing, and its exit code still said success | The generated rule file was written in text mode, so every line carried a CR and no pattern matched | Compare an object id (tree or HEAD) before and after, never the exit code alone; the writer emits bytes with plain LF, and a changed tree is the only proof a rule matched |
| A push hook crashed on a branch that had just been rewritten | The hook read the upstream to decide what changed, and a rewritten branch has no upstream ref yet | Treat a missing upstream as "unknown, run everything" rather than an error; `write_timings` keeps the run and records it as dirty |
| A history scan reported files that no push can ever carry | It read every ref, and harness scratch refs hold old copies of the tree | Scan branches and tags, which are what a push moves; a scratch ref never leaves the machine |
| Re-ran a whole-history scan between each fix | Each pass cost 25 to 90 seconds of CPU for one answer | Collect every term and path from one pass, fix them together, then scan once |
| A file moved between folders left its old copy behind in history | Only the current path was inverted, and the earlier path still held the content | Invert per historical path, or by name glob, so every copy goes at once |
| A tracked shortcut carried a machine path into history | A binary file was committed as if it were content | Do not track shortcuts or other binaries; remove the path rather than trying to rewrite bytes inside it |

- A failing call is not a repository defect: look for its class above before retrying, and add a row when none fits. A retry of the same command is not a fix.
- Harness-specific symptoms - sandbox denials, low-integrity labels, the 60 s foreground cap, heredocs, `python -c` quoting and a long silent run - stay in [the harness page](DEEPSEEK-HARNESS.md), which owns how this host behaves rather than how a step went wrong.
