# Resolved questions

Decisions that are settled, each kept for its reason and for what would reopen it. Undecided ones live in
[open questions](OPEN-QUESTIONS.md), and agreed work in [TODO](TODO.md).

- **Code similarity.** The 0.95 screen runs opt-in; it caught two near-identical ASR `start` functions and a loader switch that converted only the UNet node.
- **Hardware specs.** Machine numbers stay in the docs by decision; revisiting them is cheap but not planned.
- **Lint strictness.** The gate stays at the [code rules](../.agents/CODE.md) limit with no inline suppressions and ruff clean repo-wide. Tightening (`ARG`, `PL`) is worth it only if a defect slips through.
- **Scoped checks.** The gate, the formatter and the test suite act on the change by default and take `--all` for the whole tree; the suite's scope is the reverse import closure of the changed modules, and a path that graph cannot model already means every class. [Validate](../scripts/tests/validate.py) and `check_repo.bat` stay exhaustive. Reopen if a scoped run passes while a full one fails.
- **Embedding index over code and docs.** Declined for now: `grep` plus the owner rules answer what arises, and an index needs its own refresh path. Revisit if the document set outgrows a diff.
- **Capability matrix evidence.** Producers record what each run used, so a row is judged rather than guessed; flagged rows are refreshed through the [TODO](TODO.md) reruns.
- **Documentation similarity.** EmbeddingGemma-2 at 0.90 with the two-unit rule, opt-in and report-only. The tree as of 2026-11-15 reported 46 pairs over 141 documents and 1,685 units; the code mode at 0.95 reported 3 pairs over 301 files and 1,730 functions. Both ran on the ROCm build because the Vulkan build crashes on a batched embedding request. [Record](reviews/EMBEDDINGS-2026-11-10.md).
- **Catalog format.** [catalog.json](../scripts/config/models/catalog.json) stays JSON: it is edited through `model_admin`, ordered writes keep diffs stable, and validation runs on save. YAML would add only a comment beside each entry, which is not worth rewriting the writer. Revisit when entry comments matter more than stable diffs.
- **Lemonade voice design.** It stays a fast-multilingual framework, not a voice-design one. Its MOSS TTS entries are weaker than Breeze 2 for characters and too heavy for the language-practice setup, so neither profile needs a test and the Kokoro comparison was not run against them.
- **Framework-reported values.** Read live at the point of use, with no disposable index: the catalog label keys every read and a single model's detail view may read its packaged spec, about 60 ms per GGUF. `model_languages.json` stays because tracked pages must render with no weight installed; its AudioCpp `locales` are compared against the spec by the suite so a copy cannot drift, while the base-code list, tiers and sources beside them are judgment no model reports.
- **Non-Python change selection.** A `.bat`, JSON, document or `pyproject.toml` edit selects no test class, and it stays that way: the [suite guide](../scripts/tests/README.md) states it beside the rule that [selection](../scripts/tests/scoped_selection.py) owns, a batch file names modules the graph cannot follow without a table to maintain, and the push run is the guarantee for a path no module names. Reopen if a config-only edit ever breaks a case that a full run would have caught.
- **Duplicate one-liners in the launchers.** Kept: `matching_server` is a protocol member, and `bind()` reads the module attribute out of its namespace, so the module-level function is the seam a caller patches. Folding it would delete that seam and leave four modules re-exporting one object. The two launcher `main` functions and the three `exe` properties are wiring, not logic.
- **Walrus in statement headers.** Allowed, and the check says so in its own docstring: `while chunk := read()` and `if preset := _preset_for(model):` put the assignment on the line where a reader looks for it, while the banned shape hides a binding inside a comprehension. Reopen only with a header that stores a value used far from the line.
- **Expression density.** Adopted as a check: operator nodes may nest three levels deep, meaning the root operator plus two inside it, and a flat chain inside one node (`a or b or c`) is read in one pass and stays allowed. A call or comprehension counts as one fact whatever it contains. The census that decided it first counted operators rather than levels, which flagged 70-odd flat chains the rule does not mean to refuse; the level measure starts clean after naming the one condition that was too deep. Counting AST nodes per physical line was measured and rejected because it mostly flags table-row f-strings. Reopen the line measure only if a real defect hides in one of those rows.
- **What gets a batch file.** A `.bat` exists for a run a person starts: it prepares the venv, titles the window, pauses and returns the exit code. An agent, a hook or a script calls `python -m` directly, because a pause would hang it. No user/internals split: the role folder already says who a batch is for, and the review wrappers beside their own tree are indexed in [batch entry points](../bat/README.md).
- **Section groups in long modules.** A prompt, never a cap: `scripts/review/checks/inventory_code.py` counts `# --- Name ---` headers and reports a file over five, so the two that carry nine (`project_config.py`, `launcher_speech.py`) are read as prompts to split when next touched. A hard cap would only regroup the same stages, and the refactored `scoped_selection.py` shows a header earning its place at four.
- **Repeated expressions.** No gate. Counting non-`self` attribute chains and binary operations repeated three or more times per function finds 75 functions and 85 repeats, which is idiomatic; the narrow version, the same expression twice inside one condition, finds two sites. Naming stays a judgment at review.
- **Vague names.** No banned list as a check. Thirty functions carry one of those names and each is an entry point whose module already states the object (`probe_runner.run`, `model_run.check`), which is the [folder rule](../.agents/FOLDERS.md) "a name states its scope" working one level up.
- **No nested calls.** Withdrawn as a repo-wide rule: 3,481 call sites in 357 files pass one call as another's argument, and idiomatic Python depends on it (`print(f(x))`). The two cases fixed in `scoped_selection.py` were a boundary call hidden inside a larger expression, which is a judgment per site.
